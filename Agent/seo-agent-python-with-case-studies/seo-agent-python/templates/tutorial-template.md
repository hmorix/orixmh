# Template: Tutorial / How-To Guide

> This template defines the standard structure for HMorix tutorials, technical guides, and step-by-step documentation. Every tutorial should help readers successfully complete a real task while remaining accurate, practical, and easy to follow.

---

# Purpose

A HMorix tutorial should:

- Teach readers how to complete a specific task.
- Break complex processes into simple, logical steps.
- Explain both **what** to do and **why** it matters.
- Help readers avoid common mistakes.
- Be useful for beginners while still valuable for experienced users.

The goal is to educate, not promote.

---

# Tutorial Structure

## 1. SEO Metadata

Generate before writing.

Include:

- SEO Title (under 60 characters)
- Primary Keyword
- Secondary Keywords
- Meta Description
- URL Slug
- Suggested Category
- Suggested Tags

---

## 2. H1

Requirements:

- Clearly state the outcome.
- Include the primary keyword.
- Be action-oriented.

Examples:

- How to build a business website
- How to connect Supabase to Node.js
- AI automation: a step-by-step guide

Avoid vague titles such as:

- Complete Guide
- Everything About
- Learn AI

---

## 3. Opening

Length:

2–3 short paragraphs.

Explain:

- What the reader will accomplish.
- Who the tutorial is for.
- Expected outcome.
- Approximate difficulty level.
- Any prerequisites.

Example:

By the end of this guide, you'll have a working React application connected to Supabase. Basic knowledge of JavaScript and Node.js is recommended.

---

## 4. Prerequisites

List only what is required.

Examples:

- Software
- Accounts
- Hardware
- API keys
- Programming knowledge
- Dependencies
- Environment variables

Keep the list concise.

---

## 5. Step-by-Step Instructions

Use numbered H2 headings.

Each step must include:

### What to do

Explain the action clearly.

### Why it matters

Briefly explain the purpose of the step.

### Example

Include one or more of the following when relevant:

- Code block
- Terminal command
- Configuration snippet
- JSON example
- Screenshot placeholder
- Diagram placeholder

Every step should move the reader toward the final outcome.

---

## 6. Verification

Explain how readers can confirm the step worked correctly.

Examples:

- Expected output
- Success message
- Screenshot
- Browser result
- Console log

Avoid assuming success.

---

## 7. Best Practices

Recommend practical improvements.

Examples:

- Security recommendations
- Performance tips
- File organization
- Naming conventions
- Error handling
- Backup strategies

Explain why each recommendation is useful.

---

## 8. Common Pitfalls

Create a dedicated troubleshooting section.

Include:

| Problem | Likely Cause | Solution |
|----------|--------------|----------|

Focus on realistic issues readers commonly encounter.

Examples:

- Missing dependencies
- Configuration errors
- Permission problems
- API authentication failures
- Incorrect environment variables

---

## 9. FAQ

Include 3–5 practical questions.

Examples:

- Why isn't this working?
- Can I use a different framework?
- Is this suitable for production?
- What are the alternatives?
- How do I troubleshoot common errors?

Provide concise, factual answers.

---

## 10. Key Takeaways

Summarize the tutorial.

Use either:

- 3–5 bullet points

or

- Two short paragraphs

Do not introduce new concepts.

---

## 11. Call to Action

Finish with a single sentence.

Reference only verified HMorix services or products when appropriate.

Example:

"If you need a custom implementation or business-specific automation, HMorix can help design and build a solution tailored to your requirements."

The CTA should be relevant to the tutorial.

---

## 12. Suggested Images

Recommend visuals where they improve understanding.

For each image include:

- Placement
- Suggested filename
- Alt text
- Optional caption

Examples:

- Dashboard screenshot
- Workflow diagram
- Terminal output
- Configuration page
- Architecture diagram

Avoid decorative images.

---

## 13. Internal Links

Recommend relevant HMorix pages.

Examples:

- Related tutorials
- Services
- Products
- Documentation
- Contact page

Only include relevant links.

---

## 14. External References

When technical accuracy requires supporting documentation, recommend authoritative sources.

Examples:

- MDN
- Node.js Documentation
- React Documentation
- Google Search Central
- OWASP
- Supabase Documentation
- PostgreSQL Documentation
- Microsoft Learn

Do not cite unreliable blogs.

---

## 15. Structured Data

Generate valid Schema.org JSON-LD.

Preferred types:

- HowTo
- Article
- BlogPosting
- FAQPage (when FAQ is included)

Include all appropriate structured data fields.

---

# Writing Rules

Every tutorial should:

- Follow a logical sequence.
- Explain both "how" and "why."
- Use active voice.
- Keep paragraphs short.
- Use numbered steps.
- Include practical examples.
- Avoid unnecessary jargon.
- Explain technical terms when first introduced.
- Never invent facts or unsupported capabilities.
- Follow the HMorix brand voice.

---

# Quality Checklist

Before publishing, verify:

- One H1 only
- Outcome-focused title
- Clear introduction
- Prerequisites included
- Numbered step-by-step instructions
- Each step explains what and why
- Code or screenshot placeholders where useful
- Verification guidance included
- Best practices section
- Common pitfalls table
- FAQ included
- Key Takeaways included
- Relevant CTA included
- Suggested images provided
- Internal and external references suggested
- SEO metadata completed
- Schema.org JSON-LD generated
- No unsupported claims or invented information

---

# Final Principle

Every HMorix tutorial should enable readers to complete a real task with confidence. Instructions should be practical, technically accurate, easy to follow, and supported by examples, troubleshooting guidance, and honest explanations.
